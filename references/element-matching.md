# Mapeamento semântico
O agente de IA associa todos os elementos do design considerando hierarquia, função, tags, classes, geometria relativa e evidências estáticas. IDs runtime devem vir da mesma coleta. Não associe por texto de mock ou somente por proximidade. Exija correspondência confiável por propriedade; ambiguidades e elementos obrigatórios ausentes ficam inconclusivos. Para listas, proponha representante por padrão visual; instâncias sem associação permanecem inconclusivas. Estados ausentes e grupos decorativos sem equivalente DOM podem ser anotados como propostas de exclusão, mas não são descartados pelo motor.

Contrato de mapping.json:
```json
{"context":{"route":"/praticar","state":"default","theme":"light","interaction":"none"},"staticStatus":"completed","staticReason":"","staticEvidence":[{"nodeId":"1:2","property":"padding-top","file":"src/Chat.css","line":12,"explanation":"Padding declarado no componente Chat"}],"matches":[{"nodeId":"1:2","runtimeId":"e5","confidence":"high","reason":"Mesma função e hierarquia"}],"excluded":[{"nodeId":"1:3","reason":"Instância repetida de mensagem dinâmica com estilo equivalente","kind":"repeated"}]}
```
Exemplo ilustrativo, não copie como evidência. Kinds permitidos: repeated, conditional, decorative. Cada exclusão exige justificativa. Para correspondência incerta, deixe o elemento sem associação; o motor registra inconclusivo. Não duplique IDs nem associe e exclua o mesmo elemento. Contexto obrigatório: route, state, theme e interaction estruturados, confirmados, sem query strings, credenciais ou dados pessoais. Não invente propriedades ou evidências. Não confunda pilha CSS com fonte efetivamente utilizada. Compare geometria somente com viewport equivalente.

## Contrato ampliado (schema 3)
- Preencha `screenLabel` com nome funcional da tela confirmado pela rota e código, e `labels` com um rótulo funcional para cada ID do design (ex.: Botão de retorno, Título da página). Não copie nomes de pessoas, textos de mocks ou segredos. IDs originais permanecem intactos.
- Faça duas passagens: primeiro associe componentes funcionais, depois resolva grupos internos e textos diretos usando evidência estática e hierarquia. Uma camada Figma não exige um nó DOM próprio. Não invente equivalências.
- `matches` aceita `kind`: `element` (padrão), `direct-text` ou `wrapper`. Para compartilhar um runtimeId, declare `properties` explícitas e disjuntas em todas as associações; propriedades disputadas ficam inconclusivas. Cada nodeId aparece uma única vez.
- Para texto direto use `kind: direct-text`, apenas quando o proprietário DOM tem `hasDirectText: true` e o código comprova o rótulo direto. Reserve para ele propriedades de texto (color, font-*, line-height, text-align); não use para dimensões ou padding.
- Para wrapper sem nó próprio, use `kind: wrapper` com escopo de padding/gap. Padding permanece inconclusivo sem caixa equivalente; gap pode ser medido por filhos correspondentes mesmo sem mapeamento do wrapper. Não exclua grupos funcionais só por falta de elemento próprio.
- Para dimensões fixas inclua `dimensionPolicy: {"width":"fixed"}` apenas se a dimensão for efetivamente fixa no código, com evidência estática de width para o mesmo nodeId. Trate height auto e regras responsivas como não comprovadas; avalie eixos separadamente.
- Exemplo parcial ilustrativo: `{"screenLabel":"Erro 404","labels":{"1:2":"Botão de retorno","1:3":"Rótulo do botão"},"matches":[{"nodeId":"1:2","runtimeId":"e5","confidence":"high","kind":"element","properties":["background-color"],"reason":"Ação principal confirmada no JSX e DOM"},{"nodeId":"1:3","runtimeId":"e5","confidence":"high","kind":"direct-text","properties":["font-size"],"reason":"Texto direto confirmado no JSX"}]}`. Complete contexto, staticStatus, staticEvidence e excluded conforme contrato original. Não copie IDs de exemplo.

As exclusões propostas em excluded são apenas registros de intenção; não autorizam not_applicable. O motor mantém as propriedades inconclusivas. Para aceitar um match é exigida referência estática válida do nodeId, além da compatibilidade básica do tipo e escopo. Se a análise estática estiver bloqueada, a associação não é considerada comprovada. Confirme contexto usando os valores enumerados em validation-rules.md; não envie descrição livre como state.
